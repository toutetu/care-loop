# CareLoop

通所介護（デイサービス）の記録アプリ。現場で書かれた記録から、リスクの兆候と目標の進捗を読み取り、職員が判断するための材料として提示します。ご家族へお渡しする連絡帳も同じ記録から作ります。

LaravelからClaude APIを呼び出し、プロンプト設計・構造化出力の検証・エラーハンドリング・費用管理までを実装した、個人開発のポートフォリオです。

## 何を作ったのか

介護記録にAIを使うと言ったとき、いちばん簡単なのは「記録を全部LLMに渡して、気づいたことを挙げてもらう」実装です。このアプリはそれをしていません。

### 数値の判定はAIに任せない

体重の減少率・水分摂取量・バイタルの異常値は、しきい値との比較で決まります。ここをLLMに投げると、同じ記録でも結果が変わりうる処理になり、なぜその結論になったのかを数値で説明できなくなります。

数値は `RiskIndicatorCalculator` が決定的に算出し、「ふらつきの記述が直近2週間で増えている」のような、読まないと分からない質的な変化だけをLLMが抽出します。画面ではどちらで検出したのかをバッジで区別して表示します。

| 検出元 | 担当 | 性質 |
|---|---|---|
| ルールベース | しきい値判定 | 同じ記録なら必ず同じ結果。根拠を数値で示せる |
| AIが記述から検出 | 自由記述の読み取り | 有用だが要確認。根拠の記録を必ず添えさせる |

デモデータには、この役割分担が見える仕込みを入れてあります。中村みつさんの体温 37.4℃ は発熱の判定基準（37.5℃）をあえて下回らせてあり、しきい値判定では検出されません。記録には「自覚症状はないが」と書かれているため、LLM側でのみ拾われます。

### AIの出力は下書きとして扱う

- 指摘には根拠となった記録を必ず添えさせ、画面からその記録を開けるようにしています（`RiskFinding::$evidence`）
- 目標の進捗評価には `insufficient_data`（判断できる材料が不足）という選択肢を用意し、記録が足りない期間に無理な評価をさせません
- AIが生成した文章を職員が書き換えると `*_edited_by_human` が立ちます。どこまでがAIの出力で、どこからが人の判断なのかを後から追えないと、法定文書として説明できません
- AIが文章を書き直すと確定（`confirmed_at`）は外れます。職員が読んでいない下書きが、そのまま記録になることはありません

### 個人情報は外部へ送らない

- お名前・ご家族の連絡先・事業所名は、APIへ送る前に `{{RESIDENT_1}}` のようなプレースホルダへ置換し、受け取ってから元に戻します（`PiiMasker`）。対応表は永続化しません
- 氏名・保険者番号・住所・既往歴はデータベース上でも暗号化しています。暗号化した項目はSQLで検索できないため、氏名カナの検索だけ HMAC-SHA256 のブラインドインデックスを別に持っています
- 音声は自社サーバーにも外部APIにも送りません。OS標準キーボードの音声入力を前提とし、アプリが受け取るのは文字列だけです

### 失敗を隠さない

LLMは失敗します。失敗の種類を12種に分け（`LlmErrorType`）、再試行してよいものと設定の見直しが必要なものを区別しています。職員には「次に何をすればよいか」が分かる日本語を返します。

呼び出しの結果・所要時間・トークン数・費用はすべて `llm_requests` に記録し、AI利用ログの画面で確認できます。成功したものだけを見せても、エラーハンドリングを作った意味が伝わらないため、失敗も種別ごとに集計して表示します。

## LLM連携機能

| ID | 機能 | 内容 |
|---|---|---|
| F-LLM-01 | 目標進捗要約 | 短期目標ごとに、記録から進捗を評価する |
| F-LLM-02 | リスク兆候抽出 | ルールベースの算出結果を渡したうえで、記述からの兆候のみ抽出させる |
| F-LLM-05 | 音声入力の三面変換 | 口語の原文から、記録用・ご家族向け・申し送り用を一度に生成する |

構造化出力（`output_config.format.json_schema`）でスキーマを指定し、受け取った値は `ResponseValidator` で再検証します。スキーマに合っていても、根拠のない内容が入っていることがあるためです。

### 実装上つまずいた点

APIの検証は JSON Schema の仕様どおりではありません。

- `object` 型のすべてのノードに `additionalProperties: false` を明示しないと 400 になる
- `enum` を持つノードの `type` を union（`["integer", "null"]`）で書くと 400 になる

どちらも各プロンプトの書き手に覚えさせるのではなく、送信直前の `JsonSchema::forApi()` で機械的に正規化しています。書き忘れても通るようにし、`JsonSchemaTest` で本番の全スキーマに正規化が効いていることを確かめています。

## 技術スタック

| 領域 | 採用技術 |
|---|---|
| バックエンド | Laravel 13 / PHP 8.4 |
| フロントエンド | Inertia.js + React 19 + TypeScript + Tailwind CSS |
| データベース | MySQL / MariaDB（第3正規形まで正規化） |
| LLM | Anthropic Claude API（`anthropic-ai/sdk`） |
| 静的解析 | PHPStan level 7（larastan）/ Laravel Pint |
| テスト | PHPUnit 213件 |

データベースの正規化方針は、各マイグレーションの `comment()` に根拠を書いています。要介護度を文字列で持たず `care_levels` に切り出した理由、`service_records` に `resident_id` と `service_date` の複合一意制約を置いた理由などです。

## ローカルでの動かし方

```bash
git clone https://github.com/toutetu/care-loop.git
cd care-loop
composer install
npm install
cp .env.example .env
php artisan key:generate
php artisan careloop:blind-index-key   # 表示された値を .env の BLIND_INDEX_KEY に設定
```

`.env` にデータベースの接続先を設定してから:

```bash
php artisan migrate --seed
npm run build
php artisan serve
```

`ANTHROPIC_API_KEY` を設定しなくても動きます。空の場合は `FakeClient` が固定のJSONを返すため、課金なしでアプリ全体の動作を確認できます。

ログイン情報は `admin@example.com` / `manager@example.com` / `staff@example.com`、パスワードはいずれも `password` です。

### 品質チェック

```bash
vendor/bin/pint        # 整形
vendor/bin/phpstan analyse
php artisan test
npm run types:check
```

## 公開デモとしての設定

ログイン情報を公開した状態で実APIを呼べるようにするため、次の守りを入れています。

| 設定 | 値 | 理由 |
|---|---|---|
| `LLM_MONTHLY_BUDGET_USD` | 3 | 月次の上限。超えると実行を拒否する |
| `throttle:llm` | 1分3回・1日40回 | 上限に達してから止まるのでは、その月のデモ全体が動かなくなる |
| `FEATURE_REGISTRATION` | false | 誰でもアカウントを作れると、実APIを無制限に呼び出せる |
| `FEATURE_PASSWORD_RESET` | false | メール送信の手配がないため、押しても何も届かない |
| `CARELOOP_DEMO` | true | `careloop:reset-demo` を許可する。本番環境では絶対に立てない |

`careloop:reset-demo` はご利用者・記録・職員をすべて削除して作り直します。本物の事業所のデータベースへ向けて実行されたら取り返しがつかないため、`CARELOOP_DEMO` が立っていなければ確認を出す前に断ります。
