# CareLoop デザインガイド

画面の見た目を決めている土台と、共通部品の使い方をまとめる。次に画面へ手を入れる人（人でも AI でも）が、同じ判断で作れるようにするための文書。

「なぜそうしたか」を先に書き、値は後ろに置く。値だけ真似ても、理由を知らなければ次の判断で崩れる。

---

## 1. 前提：誰が使う画面か

- 介護職員は **50〜60 代が中心**。加齢でコントラスト感度が落ちる。
- 現場では **片手しか空いていない**。もう片方の手でご利用者を支えている。
- 手袋や濡れた手で触る。屋外（送迎中）の明るい場所でも読む。
- 主端末は **iPhone（Safari）**。管理者はタブレット横向きか PC。

この前提から、次の 3 つは **変えない**。

| 決まり                 | 値                                          | 根拠                                       |
| ---------------------- | ------------------------------------------- | ------------------------------------------ |
| 文字のコントラスト     | 7:1（WCAG AAA）以上。明暗どちらのモードでも | AA（4.5:1）では 50〜60 代に足りない        |
| タップ領域             | 最小 44×44px、隣接要素との間隔 8px 以上     | 手袋の指で隣を押す事故を減らす             |
| スマートフォンの主操作 | 画面下 3 分の 1（下部タブバー、送信ボタン） | 親指だけで届く範囲。左上の角は最も届かない |

---

## 2. ブランド

### ロゴ

- 正本は 2 つ。同じ絵を JSX と SVG で持っている。
    - `resources/js/components/brand-mark.tsx` — 画面内で使う React 部品
    - `public/favicon.svg` — ブラウザのタブ用
- `public/favicon.ico` と `public/apple-touch-icon.png` はこの SVG から作る。手で描かない。

```bash
node scripts/build-icons.mjs
```

- 由来：作者が別のアプリ用に作ったアイコン「おやこしずく」の色を青緑に変えたもの。真珠で縁取った輪が **ループ**、寄り添う 2 つのしずくが **ケア** を表す。
- 色は固定。暗モードでも変えない。角丸の下地ごと 1 つの絵であり、アプリのアイコンと同じ見た目を画面内でも出す。
- 使う場所：サイドバー左上（`app-logo.tsx`）、スマートフォンのヘッダー左端（`app-sidebar-header.tsx`）、認証画面の上（`auth-simple-layout.tsx`）、トップページ。

`BrandMark` は同じページに複数置ける。グラデーションの `id` を `useId` で作っているため、2 つ描いても片方がもう片方の定義を拾わない。

### ブランド色

青緑、色相 195。`resources/css/app.css` の `:root` と `.dark` で定義している。

色相 195 を選んだ理由は、意味を持つ 5 色のどれとも隣り合わないこと。

| 意味色        | 色相    | 表すもの                             |
| ------------- | ------- | ------------------------------------ |
| danger        | 27      | 要対応。今日中に見る                 |
| warning       | 85      | 注意。放置しない                     |
| success       | 152     | 済み・良好                           |
| ai            | 305     | AI が出した。人が目で確かめる        |
| deterministic | 無彩色  | 数値としきい値から算出した事実       |
| **brand**     | **195** | ボタン・リンク・選択中・フォーカス枠 |

緑寄り（170 以下）にすると success と、青寄り（230 以上）にすると ai と見分けがつきにくくなる。

## 3. 配色の構造

### 面は 3 段

枠 ＞ 紙面 ＞ カード の順に明るくし、色味は薄くなる。枠線だけで区切ると全部が同じ白になり、どこが操作の単位か見えなかった。

| 面     | トークン       | 明モード                 | 暗モード                |
| ------ | -------------- | ------------------------ | ----------------------- |
| 枠     | `--sidebar`    | `oklch(0.945 0.022 195)` | `oklch(0.15 0.012 195)` |
| 紙面   | `--background` | `oklch(0.97 0.01 195)`   | `oklch(0.17 0.012 195)` |
| カード | `--card`       | `oklch(1 0 0)`           | `oklch(0.21 0.012 195)` |

カードは `shadow-card`（`--card-shadow`）で紙面から浮かせる。影の色も青緑に寄せてあり、灰色に濁らない。

### ベタ塗りの primary

| モード | `--primary`            | 文字                  | 比率    |
| ------ | ---------------------- | --------------------- | ------- |
| 明     | `oklch(0.44 0.09 195)` | 白                    | 7.26:1  |
| 暗     | `oklch(0.8 0.1 190)`   | `oklch(0.2 0.02 195)` | 10.05:1 |

暗モードで暗い青緑に白文字を載せると沈んで見えるため、明るい青緑に濃い文字を載せる。

### 意味色は 2 軸

軸 1（danger / warning / success）は **対応の要否**、軸 2（ai / deterministic）は **情報の出どころ**。軸をまたいで同じ色を使わない。「両方で検出」は 3 色目を作らず、ai と deterministic のバッジを 2 枚並べる。覚える色を増やさないため。

意味色の値は `app.css`、画面への割り当ては `resources/js/lib/care-presentation.ts` だけが持つ。画面側で色クラスを直書きしない。

### 色を変えるときの手順

1. `app.css` の値を変える。
2. 比率を測る。文字は 7:1 以上、ベタ塗りも 7:1 を目安にする。

```bash
node scripts/contrast.mjs "oklch(0.44 0.09 195)" "oklch(1 0 0)"
```

3. 明暗の両方で画面を開いて確かめる。
4. `app.css` のコメントにある比率を書き直す。

## 4. 文字

- 書体は Noto Sans JP を先頭に置く（`vite.config.ts` の `bunny()` で読み込む）。OS 任せにすると端末ごとに字面が変わる。
- 尺度を 1 段引き上げてある。`text-sm` が 16px、`text-base` が 18px。各画面で大きくするのではなく、`app.css` の `@theme` で底上げしている。
- 行間は `body` で 1.7。長い申し送りを追い直す回数が減る。
- 表の数字は等幅（`font-variant-numeric: tabular-nums`）。桁で揃う。

見出しの階層は 3 つだけ。

| 場所               | クラス                              | 部品         |
| ------------------ | ----------------------------------- | ------------ |
| 画面の見出し（h1） | `text-xl font-bold tracking-tight`  | `PageHeader` |
| カードの見出し     | `text-base font-semibold`           | `Section`    |
| 数値カードの数字   | `text-3xl font-bold tracking-tight` | `StatCard`   |

## 5. 共通部品

置き場所は `resources/js/components/`。`ui/` は shadcn/ui の素の部品で、業務の意味を持つ部品は `care/` に置く。

| 部品               | ファイル                   | 役割                                                                               |
| ------------------ | -------------------------- | ---------------------------------------------------------------------------------- |
| `BrandMark`        | `brand-mark.tsx`           | ロゴ。`className` で大きさ、`title=""` で飾り扱い                                  |
| `PageHeader`       | `care/page-header.tsx`     | 画面の見出し。`icon` / `title` / `meta` / `description` / `actions`                |
| `Section`          | `care/section.tsx`         | 見出しと補足と右側の操作を持つカード                                               |
| `StatCard`         | `care/section.tsx`         | 数値ひとつのカード。`tone` で色（下記）。`href` か `onClick` で押せる              |
| `EmptyState`       | `care/section.tsx`         | 一覧が空のときの文言                                                               |
| `SourceBadge` ほか | `care/badges.tsx`          | 検出元・重要度・記録の状態・進捗評価のバッジ。色は `care-presentation.ts` が決める |
| `NOTICE_SURFACE`   | `lib/care-presentation.ts` | 注意書きの囲み（warning / ai / danger）                                            |
| `MobileTabBar`     | `mobile-tab-bar.tsx`       | スマートフォンの下部タブバー。毎日使う 3 つ＋その他                                |
| `Button`           | `ui/button.tsx`            | 全サイズ高さ 44px 以上。`neutral` は戻る・キャンセル専用                           |

### `StatCard` の tone

| tone      | 面     | 使う場面                              |
| --------- | ------ | ------------------------------------- |
| `default` | 白     | 件数の表示                            |
| `danger`  | 薄い赤 | 要対応のリスク                        |
| `warning` | 薄い黄 | 未確定の記録、AI 処理の失敗           |
| `ai`      | 薄い紫 | AI 下書きで職員がまだ読んでいないもの |

以前は全部を赤にしていたが、4 枚中 3 枚が赤くなり、本当に急ぐものが埋もれた。

### 画面の型

業務画面は次の順で組む。

```tsx
<div className="flex flex-col gap-4 p-4">
    <PageHeader icon={...} title="..." meta={...} actions={...} />
    <div className="grid grid-cols-2 gap-3 sm:gap-4 lg:grid-cols-4">
        <StatCard ... />
    </div>
    <Section title="..." description="...">
        ...
    </Section>
</div>
```

見出しの並びや余白を画面ごとに手書きしない。字の大きさが画面ごとに少しずつ違い、ページを移るたびに見出しの位置が動いていたのを、`PageHeader` に寄せて止めた。

### 紹介ページ（トップページ）の部品

`resources/js/pages/welcome.tsx` は業務画面ではなく、採用担当者に向けた紹介ページ。構成は「なぜ → どう → 何を」の順で、01 背景と課題 → 02 解決の考え方 → 03 AI の使い方 → 04 UI → 05 デモ → 06 技術。文章は三人称（「作者は」）で、出典は要件定義書の 1・2・7 章と F-18。部品は `resources/js/components/intro/` に置く。

| 部品                    | ファイル                 | 役割                                                                                        |
| ----------------------- | ------------------------ | ------------------------------------------------------------------------------------------- |
| `IntroSection`          | `intro-section.tsx`      | 番号つきの区画。`id` は目次のリンク先。`band` で薄い帯にする                                |
| `IconCard`              | `icon-card.tsx`          | 絵柄つきの説明カード。`tone` は brand / ai / warning。面の色は変えず、絵柄の色だけ変える    |
| `ChallengeSolutionList` | `challenge-solution.tsx` | 「課題 → 工夫」を 1 行 1 対で並べる。スマートフォンでは上下に積み、矢印を下向きにする       |
| `Screenshot`            | `screenshot.tsx`         | 実際の画面写真。`kind` が desktop ならブラウザ風、mobile なら端末風の枠。暗モードは少し暗く |
| `FlowFigure`            | `flow-figure.tsx`        | 「1 回の入力から 3 つの出口」と記録の循環の図。画像ではなく HTML で描く                     |

本文（課題・工夫・見どころ・技術構成の文言）は `welcome.tsx` の先頭に定数として置いてある。文言を直すときはそこだけ触る。数字（テスト件数、エラー種別の数）は実装に合わせて手で直す。

写真は `public/images/intro/` にあり、`scripts/capture-screenshots.mjs` で撮り直す（7 節）。ファイル名と `<img src>` は対応しているので、名前を変えたら両方直す。

---

## 6. 変えてはいけないもの

- 意味色の色相と 7:1 の比率。
- 意味色の 2 軸の分け方。3 色目を足さない。
- `text-sm` = 16px の底上げ。iOS Safari の自動ズーム（16px 未満で発生）も止めている。
- ボタンの高さ 44px。`size="sm"` は「狭い」であって「低い」ではない。
- 下部タブバーの位置と 4 つの構成。

## 7. 変えたあとに確かめること

```bash
npm run check        # 整形と lint
npm run types:check  # 型
php artisan test     # 340 件
```

画面は次の 4 通りで開く。

1. 明モード、PC 幅（1280px）
2. 暗モード、PC 幅
3. 明モード、スマートフォン幅（390px）
4. 暗モード、スマートフォン幅

ブラウザの開発ツールで `prefers-color-scheme` を切り替えれば暗モードになる（アプリの設定が「システム」のとき）。

### 画面写真の撮り直し

トップページ（`resources/js/pages/welcome.tsx`）には実際の画面の写真を載せている。配色や部品を変えたら撮り直す。

```bash
npx @puppeteer/browsers install chrome@stable --path ~/.cache/puppeteer   # 初回だけ
php artisan serve                                                          # 別のターミナル
node scripts/capture-screenshots.mjs
```

出力は `public/images/intro/`。Windows の Edge は headless で起動せずに終了することがあるため、Chrome for Testing を使う（`scripts/lib/browser.mjs`）。撮ったあとは、架空のご利用者の名前しか写っていないことを目で確かめる。

## 8. 経緯

2026-09-15 に、Laravel スターターキット初期状態の無彩色から、ロゴを起点にした青緑の配色へ変えた。変更前は色が全部グレーで、ロゴが Laravel のままで、背景もカードも白だった。このときに `PageHeader` と `BrandMark` を作り、`StatCard` の `tone` を danger / warning / ai に分けた。
