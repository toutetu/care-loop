# デプロイ手順（Laravel Cloud）

公開デモを Laravel Cloud に配置する手順です。同じ構成で作り直せるよう、値と理由を残しています。

> AWS Lightsail のサーバー 1 台に、サーバーの設定から自分で行って配置する手順は [06_デプロイ手順_AWS.md](06_デプロイ手順_AWS.md) にあります。環境変数の値と理由は、この文書の 3 章を共通で使います。

- リポジトリ: https://github.com/toutetu/care-loop
- デモ: https://care-loop-production-peqetb.laravel.cloud/
- 想定コスト: Laravel Cloud の利用料 + Claude API 月 $3 まで

---

## 0. 前提

| 項目         | 値                                                                           |
| ------------ | ---------------------------------------------------------------------------- |
| PHP          | 8.4                                                                          |
| Node         | 22 以上                                                                      |
| データベース | MySQL 8                                                                      |
| キュー       | Laravel Cloud のマネージドキュー（Flex / 512 MiB）。AI処理を非同期で実行する |

セッション・キャッシュはデータベースを使うため、Redis は不要です。

---

## 1. アプリケーションを作成する

1. [cloud.laravel.com](https://cloud.laravel.com) にログインする
2. **Create Application** → GitHub を連携し、`toutetu/care-loop` を選ぶ
3. ブランチは `main`
4. リージョンは `ap-northeast-1`（東京）を選ぶ

---

## 2. データベースを追加する

1. アプリケーションの **Database** から MySQL を追加する
2. 接続情報（`DB_*`）は Laravel Cloud が自動で環境変数に挿入する

> MariaDB ではなく MySQL でよい理由: マイグレーションは `comment()` と複合一意制約しか使っておらず、どちらでも動く。ローカルの XAMPP が MariaDB なのは開発環境の都合にすぎない。

---

## 2.5. マネージドキューを追加する

AI処理（リスク兆候抽出・目標進捗要約・音声の三面変換）をバックグラウンドで実行するために使います。

### なぜ必要か

AI処理は Claude API の応答を待つため、1回の呼び出しに数十秒かかります。再試行が重なると合計で数分に達することがあり、その前に手前のゲートウェイ（Cloudflare）がリクエストを切ります。実際に本番で「リスク兆候を抽出」を押すと、英語の `Gateway time-out`（504）だけが画面に残りました。

実行をキューへ移すと、押した直後に画面を返し、処理はワーカーが引き取ります。画面は `llm_jobs` の状態をポーリングし、完了した時点で結果を描きます（`RunLlmFeature` ジョブ、要件定義 7.5節）。

### 手順

1. 環境を開き、**Add compute** → **Managed queue** を選ぶ
2. 次の値を設定する

| 項目        | 値                 | 理由                                                                                                                                                                               |
| ----------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| クラス      | **Flex** / 512 MiB | キューが空のときワーカーがゼロになる（scale-to-zero）。Pro は常に1台動かし続けて継続課金される。処理の大半はAPIの応答待ちで、メモリは使わない                                      |
| `--timeout` | **90**             | Flex はスポット枠で、中断時に与えられる猶予が90秒。これより長くしても守られない。アプリ側の `LLM_JOB_TIMEOUT_SECONDS`（85）と `LLM_DEADLINE_SECONDS`（70）はこの値より短くしてある |
| `--tries`   | **1**              | 再試行は `LlmGateway` が失敗の種類ごとに判断している。Laravel 側でも再試行すると、同じAPI呼び出しに二重で課金される                                                                |
| `--backoff` | 0                  | `--tries 1` なので意味を持たない                                                                                                                                                   |
| `--force`   | off                | メンテナンスモード中にジョブを動かす理由がない                                                                                                                                     |
| Min workers | **0**              | これが scale-to-zero の本体                                                                                                                                                        |
| Max workers | **1**              | 同時に複数のAI処理を走らせると、月次の費用上限に短時間で到達する                                                                                                                   |

Preview command がこうなっていれば正しい：

```
php artisan queue:work cloud --queue=default --timeout=90 --tries=1
```

3. **Deploy** を押す。押すまで `QUEUE_CONNECTION=cloud` は有効にならない

> **`QUEUE_CONNECTION=cloud` の横に出る ⚠ Override は正常です。**
> `.env` に書いた `database` を Laravel Cloud が上書きするという通知で、それが望んだ動作です。`Override` のリンクは押さないでください。

### ワーカーの動作を確認する

Deploy が終わったら、Laravel Cloud の **Commands** で次を実行します。確認用のジョブを積み、ワーカーが拾うまで待って合否を出します。

```bash
php artisan careloop:queue-check
```

```
  キュー接続 : cloud
  確認用のジョブを積みました。ワーカーの応答を待ちます…
  ワーカーが応答しました（2.3 秒）
```

Flex はワーカーがゼロから起動するため、初回は10〜20秒かかることがあります。30秒待っても応答がなければ、Deploy を押したか、**Monitoring → Queues** でワーカーが増えているかを確認してください。

ログイン後の「AI処理の実行状況」にも、ワーカーの最終稼働時刻が出ます。

### ワーカーが無いとどうなるか

ジョブは `queued` のまま処理されず、エラーも出ません。黙って待ち続ける状態を作らないよう、画面は待機時間で段階を分けて出します。

| 待機時間   | 画面                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------- |
| 60秒まで   | 「待機中です。完了すると自動で表示が更新されます」                                                               |
| 60秒〜10分 | 「まだ処理が始まっていません。処理する仕組みが止まっている可能性があります」                                     |
| 10分以上   | 失敗として扱う。同じ対象への再実行を受け付け、ワーカーが復旧してもそのジョブは実行しない（費用だけがかかるため） |

### 費用の目安

画面に出る **「up to $8.84/mo」は天井**で、1ワーカーが24時間365日動き続けた場合の額です。Min workers = 0 なので、実際は処理中の秒数だけ課金されます。

AI実行が月24回、1回10秒として、コンピュート $0.0007 ＋ キュー操作 $0.0001 ＋ ポーリングの基本料 $0.13 ＝ **月 $0.13 程度**。Starter の月 $5 クレジットに収まります。

## 2.6. スケジューラを有効にする

### なぜ必要か

デモは、見に来た人がいつ開くか分かりません。作り置きのデータは日が経つほど「最終記録は3ヶ月前」になり、動いていないシステムに見えます。

毎朝 9:00（Asia/Tokyo）に `careloop:demo-day` を動かし、**その日ぶんの記録を朝9時の状態で**用意します。送迎車が着き、到着時のバイタルを測り終えたところ——入浴も食事もまだ、原文（音声入力）だけが入っていて、AIは動かしていない、確定もしていない状態です。見に来た人に触ってもらう余地が残ります。

前日以前の未確定の記録は、職員が書き終えて確定したものとして埋めます。未確定のまま積み上がると、ダッシュボードの「未確定の記録」が増え続け、見せたい数字が読めなくなるためです。

毎日 3:00 には `careloop:purge-expired-records` を動かし、利用終了日から保存期間（5年）を過ぎたご利用者の情報と記録を物理削除します（要件定義 9.3.2 の施策6）。デモのご利用者には利用終了日がないので、何も消えません。

### 手順

**Scheduler**（`php artisan schedule:run` を毎分実行する仕組み）を有効にします。有効にしないと、`routes/console.php` の登録があっても何も起きません。

1. 環境の **Environment** タブを開く（**Settings** タブではない）
2. 構成図の **App cluster** のカードを押す（Managed queue ではない）
3. 右に開く **App cluster settings** の **Scheduler** をオンにする
4. **Update** を押し、続けて **Deploy** する

`careloop:demo-day` の予定は `CARELOOP_DEMO=true` のときだけ登録されます（`routes/console.php`）。本物の事業所環境では登録されないので、毎朝エラーで終わる予定が残ることはありません。保存期間を過ぎた記録の削除は、本物の事業所環境でこそ要る処理なので、常に登録します。

### 費用

「毎分」と書いてあっても、**眠っているアプリを毎分起こすわけではありません**。Laravel Cloud はデプロイのたびに `schedule:list` の結果を記録し、予定の時刻にだけアプリを起こします（[Scheduled Tasks](https://laravel.com/cloud/docs/scheduled-tasks)）。

- この作品の予定は 9:00 と 3:00 の2つなので、眠っているアプリが起きるのは1日2回
- 起きたあとは **Sleep after**（5分）のあいだ動いてから、また眠る
- 1日10分、月に約5時間。App cluster（Flex 512 MiB）の表示「up to $7/mo」は24時間動かし続けた場合の額なので、増える費用は **月 $0.05 程度**

予定の間隔を Sleep after より短くすると、アプリが眠れなくなり、24時間動き続けた額に近づきます。予定を足すときは、間隔を Sleep after より長くします。

### 動作を確認する

Laravel Cloud の **Commands** から、登録されているかを見ます。

```bash
php artisan schedule:list
```

`careloop:demo-day` が `09:00`、`careloop:purge-expired-records` が `03:00` で出ていれば登録できています。手で1回動かして結果を見ることもできます。

```bash
php artisan careloop:demo-day
```

```
  INFO 2026-09-15 ぶんの記録を 8 件作り、前日までの 1 件を確定しました。
```

同じ日に二度動かしても、その日ぶんが二重に積まれることはありません。すでに記録がある方は飛ばします。

> 日付を指定して動かすこともできます（`--date=2026-09-14`）。デプロイ直後に前日ぶんを作りたいときに使います。

保存期間の削除は、消さずに件数だけを確かめられます。消したものは戻せないので、手で動かすときは先にこちらを使います。

```bash
php artisan careloop:purge-expired-records --dry-run
```

```
  INFO 利用終了日が 2021-10-04 より前のご利用者は 0 名、記録は 0 件です。--dry-run のため削除していません。
```

## 3. 環境変数を設定する

**Environment** に以下を設定します。`APP_KEY` と `DB_*` は Laravel Cloud が自動で設定するため、手で入れる必要はありません。

### 基本

```
APP_NAME=CareLoop
APP_ENV=production
APP_DEBUG=false
APP_TIMEZONE=Asia/Tokyo
APP_LOCALE=ja
APP_FALLBACK_LOCALE=en
APP_FAKER_LOCALE=ja_JP
```

`APP_URL` は Laravel Cloud が払い出したURLに合わせます。

### 保存とセッション

```
DB_CONNECTION=mysql
SESSION_DRIVER=database
CACHE_STORE=database
FILESYSTEM_DISK=local
MAIL_MAILER=log
```

`QUEUE_CONNECTION` は手で入れません。マネージドキューを追加すると Laravel Cloud が `cloud` を注入します（2.5節）。

### LLM 連携

```
LLM_DRIVER=claude
ANTHROPIC_API_KEY=（Anthropic Console で発行した値）
LLM_DEFAULT_MODEL=claude-sonnet-5
LLM_MONTHLY_BUDGET_USD=3
LLM_TIMEOUT_SECONDS=60
LLM_MAX_RETRIES=2
LLM_DEADLINE_SECONDS=70
LLM_JOB_TIMEOUT_SECONDS=85
```

`LLM_DEADLINE_SECONDS`（1回の実行にかけてよい合計時間）と `LLM_JOB_TIMEOUT_SECONDS`（ワーカーがジョブを打ち切る時間）は、マネージドキューの `--timeout`（90）より短くします。長くすると、打ち切られたことがアプリ側に記録されないままジョブが消えます。

### モデルの選び方

1回あたり入力4,000／出力1,500トークンとしたときの試算です。

| モデル             | 1回あたり | 月 $3 での回数 |
| ------------------ | --------- | -------------- |
| `claude-opus-5`    | $0.058    | 約 50 回       |
| `claude-sonnet-5`  | $0.023    | 約 130 回      |
| `claude-haiku-4-5` | $0.012    | 約 260 回      |

**既定を Sonnet にしている理由**: リスク兆候抽出と目標進捗要約は、記述から質的変化を読み取ったり「判断できる材料が不足」と言えたりすることが機能の要点です。判断を伴う処理で安価なモデルに落とすと、無理に評価を選ぶ方向へ傾き、このアプリで見せたい挙動が出にくくなります。

**機能ごとに分けられます。** 音声入力の三面変換は口語を文体変換するだけで判断を伴わないため、Haiku で十分です。試行回数が多くなりがちな機能でもあります。

```
LLM_MODEL_TRANSFORM=claude-haiku-4-5
```

これで音声変換だけ Haiku になり、他は `LLM_DEFAULT_MODEL` のままです。`LlmFeature::model()` が「機能別指定 → 既定」の順に解決します。

> **モデル名は `config/llm.php` の `pricing` のキーと一致させてください。**
> 日付サフィックス付き（`claude-haiku-4-5-20251001`）は一致しません。
> 一致しない場合、単価が分からないため**実行前に中止されます**（要件定義 7.4節 #13）。
> AI利用ログには「料金表にないモデル」として記録されます。
>
> 以前は費用 0 として記録していましたが、それでは月次上限が永久に発動せず、
> 課金だけが発生する状態になるため、止める方針へ変更しました。

**APIキーについて**: この値はチャットや Issue に貼らないでください。Laravel Cloud の環境変数画面に直接入力します。誤って公開した場合は、Anthropic Console で即座に失効させて再発行してください。

`ANTHROPIC_API_KEY` を空にすると `FakeClient` が固定のJSONを返します。課金せずにデモを動かしたい期間はこれで足ります。

### ブラインドインデックス

```
BLIND_INDEX_KEY=（下記のコマンドで生成した値）
```

手元で生成します。

```bash
php artisan careloop:blind-index-key
```

> **一度設定したら変更しないこと。** 変更すると、保存済みの `name_kana_hash` がすべて無効になり、氏名カナの検索ができなくなります。作り直すには全ご利用者の氏名カナを復号して再計算する必要があります。

### 公開デモとしての設定

```
CARELOOP_DEMO=true
FEATURE_REGISTRATION=false
FEATURE_PASSWORD_RESET=false
```

| 変数                             | 理由                                                                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `CARELOOP_DEMO`                  | `careloop:reset-demo` と毎朝の `careloop:demo-day` を許可する。パスキーも既定で閉じる。**本物の事業所環境では絶対に立てない**                    |
| `FEATURE_REGISTRATION`           | ログイン情報を公開したまま登録も開けておくと、実APIを無制限に呼び出せる                                                                          |
| `FEATURE_PASSWORD_RESET`         | メール送信の手配がないため、押しても何も届かないリンクになる                                                                                     |
| `FEATURE_PASSKEYS`（設定しない） | 設定しなければ `CARELOOP_DEMO=true` のとき閉じる。見に来た人は役割のボタンでログインし、デモのアカウントは共用なので、個人の顔認証を登録させない |

## 4. ビルドとデプロイのコマンド

**Build commands**:

```
composer install --no-dev --optimize-autoloader
npm ci
npm run build
```

> `resources/js/routes` と `resources/js/actions`（Wayfinder の生成物）は Git 管理外です。`npm run build` の中で Vite プラグインが `php artisan wayfinder:generate` を呼び、毎回生成します。この手順はデータベースに接続できない状態でも動くことを確認済みです。

**Deploy commands**:

```
php artisan migrate --force
```

## 5. 初回のみ：デモデータを投入する

デプロイ完了後、Laravel Cloud のコンソールで一度だけ実行します。

```bash
php artisan db:seed --force
```

ご利用者20名・約3ヶ月分の記録・リスク抽出結果・目標進捗が入ります。

> **`db:seed` を使ってよいのは、データが1件も入っていないときだけです。**
> `DemoDataSeeder` は事業所・職員・ご利用者を素直に `create()` します。
> 途中まで入った状態で再実行すると、メールアドレスの一意制約で落ちます。
> 2回目以降は下記の `careloop:reset-demo` を使ってください。

### シードが途中で失敗したとき

環境変数が足りないと、`CareLevelSeeder` は通って `DemoDataSeeder` の途中で止まります。
このとき事業所と職員だけが入った中途半端な状態になります。

よくある失敗:

```
In BlindIndex.php line 60:
  BLIND_INDEX_KEY が設定されていません。
```

`BLIND_INDEX_KEY` を設定したうえで、`db:seed` ではなく作り直しコマンドを使います。
途中まで入ったデータを消してから入れ直すためです。

```bash
php artisan careloop:reset-demo --force
```

このコマンドには `CARELOOP_DEMO=true` が必要です。

### 2回目以降にデータを作り直す場合

```bash
php artisan careloop:reset-demo --force
```

見に来た人が記録を書き換えるため、数週間で説明したい筋書き（佐藤ハナの体重減少とふらつき、中村みつの微熱）が崩れます。そのときに実行します。

> 本番環境では `migrate:fresh` と `db:wipe` を禁止しています（`AppServiceProvider` の `prohibitDestructiveCommands`）。取り違えて本物のデータを消すことを防ぐためで、この方針は変えません。デモデータの入れ直しだけを行う専用のコマンドを別に用意しています。

## 7. デプロイ後にすること

README のデモURLを実際のものに差し替えます。

```markdown
**デモ**: https://（払い出されたURL）
```
