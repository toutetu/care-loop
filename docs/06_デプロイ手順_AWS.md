# デプロイ手順（AWS Lightsail）

公開デモを AWS Lightsail のサーバー 1 台に配置する手順です。Laravel Cloud 版（[02_デプロイ手順.md](02_デプロイ手順.md)）では Laravel Cloud が代わりに行っていたサーバーの設定を、スクリプトと設定ファイルにして [`deploy/lightsail/`](../deploy/lightsail/) に置いています。

- 想定コスト: Lightsail 月 $7（税別）＋ ドメイン代（年額）＋ Claude API 月 $3 まで
- 所要時間: 画面の操作が 1 時間ほど、スクリプトの実行が 10〜20 分

---

## 0. 構成と、その理由

| 役割          | ここで使うもの                                  | Laravel Cloud では    |
| ------------- | ----------------------------------------------- | --------------------- |
| サーバー      | Lightsail（東京・Ubuntu 24.04 LTS・メモリ 1GB） | 自動で用意される      |
| Web サーバー  | nginx                                           | 自動                  |
| PHP           | PHP 8.4（PHP-FPM）                              | 自動                  |
| データベース  | MySQL 8（同じサーバーの中）                     | 画面から MySQL を追加 |
| AI 処理の実行 | データベースのキュー ＋ systemd のワーカー      | マネージドキュー      |
| HTTPS         | Let's Encrypt（certbot が自動で更新）           | 自動                  |
| 本番への反映  | `deploy.sh` を手で実行                          | main へのマージで自動 |
| OS の更新     | セキュリティ更新を毎日自動で適用                | 不要                  |

### 1 台に全部載せる理由

役割ごとに別のサービスへ分けると、月額が数倍になります。Lightsail のマネージドデータベースは月 $15 から、ロードバランサーは月 $18 です。公開デモの負荷は数人の閲覧で、分ける理由がありません。

1 台で完結できるのは、アプリの作りによるところも大きいです。セッション・キャッシュ・キューをすべてデータベースに置き、ファイルのアップロードもないため、Redis やファイル置き場を足さずに済みます。定期実行は、デモの1日ぶんを毎朝つくる予定だけで、OS の systemd タイマーが毎分 `schedule:run` を呼べば足ります。

### メモリ 1GB（$7）のプランにした理由

- **512MB（$5）では足りません。** 1 台で MySQL・画面のビルド（`npm run build`）・キューワーカーを動かすためです。メモリが尽きると、Linux は動いているプロセス（多くは MySQL）を強制終了し、デモが止まります。
- 1GB でも、画面のビルドの一瞬だけ足りなくなります。これはスワップ（メモリが足りないときにディスクを代わりに使う領域）2GB で吸収します。`setup.sh` が作ります。
- IPv6 専用のプラン（$3.5〜）は、IPv6 に対応していない回線から開けないため使いません。
- 足りなくなったら、スナップショットから大きいプランのサーバーを作り直せます。

## 1. AWS アカウントと請求アラート

1. https://aws.amazon.com/ から AWS アカウントを作ります。クレジットカードの登録と電話での確認があります。
2. ログインしたら、右上のアカウント名 → **請求とコスト管理**（Billing and Cost Management）→ **予算**（Budgets）→ **予算を作成**を開きます。
3. テンプレートは **月次コスト予算**（Monthly cost budget）、金額は **$10**、通知先に自分のメールアドレスを入れて作成します。

Lightsail はプラン料金が月の上限なので、請求が $7 を超えることは通常ありません。アラートは、ほかのサービスを誤って作ったときに気づくためのものです。

> **新規アカウントのクレジットについて**
> 2025 年 7 月以降に作ったアカウントには最大 $200 のクレジットが付き、6 か月間の無料プランで Lightsail にも使えます。
> ただし無料プランのままだと、**6 か月後にアカウントが閉鎖され、デモも止まります**。選考などで公開を続けるなら、それまでに有料プランへ切り替えます。残っているクレジットは引き継がれます。
> クレジットは 1 人 1 アカウントまでです。受け取るために複数のアカウントを作ると対象外になります（[AWS Free Tier の規約](https://aws.amazon.com/free/terms/)）。

## 2. サーバーを作る

[Lightsail の画面](https://lightsail.aws.amazon.com/) で **インスタンスの作成**（Create instance）を押し、次の値で作ります。

| 項目                     | 値                                  | 理由                                                                                                         |
| ------------------------ | ----------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| リージョン               | 東京（ap-northeast-1）、ゾーン A    | 使う人が日本にいる                                                                                           |
| プラットフォーム         | Linux/Unix                          |                                                                                                              |
| 設計図（ブループリント） | **OS のみ** → **Ubuntu 24.04 LTS**  | `setup.sh` はこの版を前提にしている。LAMP などアプリ入りの設計図は、ファイルの置き場所が独特で手順と合わない |
| ネットワークの種類       | **デュアルスタック**                | IPv6 専用は、開けない回線がある                                                                              |
| プラン                   | **$7 USD**（1GB・2 vCPU・40GB SSD） | 0 章                                                                                                         |
| インスタンス名           | `careloop`                          |                                                                                                              |

画面の文言は AWS の更新で変わることがあります。見当たらないときは、近い名前のものを選んでください。

---

## 3. 固定 IP とファイアウォール

作ったインスタンスを開き、**ネットワーキング**（Networking）タブで次の 3 つを行います。

1. **静的 IP をアタッチ**（Attach static IP）→ 名前を `careloop-ip` にして作成します。
    - サーバーの住所（IP アドレス）を固定するためです。固定しないと、サーバーを止めて起動し直したときに IP が変わり、ドメインの向き先が外れます。
    - インスタンスに付けている間は無料です。外したまま 1 時間を超えると課金されます。
2. **IPv4 ファイアウォール**で **ルールを追加**（Add rule）→ アプリケーション **HTTPS**（TCP 443）を追加します。**IPv6 ファイアウォール**にも同じものを追加します。
3. SSH（TCP 22）の行の鉛筆アイコンを押し、**Lightsail ブラウザ SSH/RDP に制限する**にチェックを入れて保存します。
    - ブラウザの SSH 画面からしか入れなくなり、世界中から届くログインの総当たりを受けなくなります。

MySQL の 3306 番は開けません。アプリは同じサーバーの中から使うためです。

---

## 4. ドメインを向ける

ドメインを買ったら、そのドメインの DNS の設定画面で **A レコード**（ドメイン名を IP アドレスに結びつける設定）を作ります。

| 項目     | 値                                                                |
| -------- | ----------------------------------------------------------------- |
| 種類     | A                                                                 |
| ホスト名 | 使いたい名前（例: `care`）。ドメインそのものを使うなら `@` か空欄 |
| 値       | 3 章の静的 IP                                                     |
| TTL      | 既定のまま                                                        |

> **買ったときから入っているレコードに注意**
> 登録会社によっては、「準備中」のページ用に A・AAAA・CNAME のレコードが最初から入っています。同じホスト名にそれが残っていると、見る人の一部がそちらへ案内されます。証明書の発行（Let's Encrypt）も失敗します。同じホスト名のレコードは、作った A レコード 1 つだけにしてください。

反映には数分〜数時間かかります。手元の PowerShell で次を実行し、静的 IP が返ってくれば反映済みです。`setup.sh` も実行時に確かめます。

```powershell
nslookup care.example.com
```

## 5. 初期設定スクリプトを実行する

1. インスタンスの **接続**（Connect）タブで **SSH を使用して接続**（Connect using SSH）を押します。黒い画面（ブラウザ SSH）が開きます。
2. 次の 2 行を実行します。`care.example.com` は 4 章で決めたドメイン名に置き換えます。

```bash
curl -fsSLO https://raw.githubusercontent.com/toutetu/care-loop/main/deploy/lightsail/setup.sh
sudo bash setup.sh care.example.com
```

3. 途中で `ANTHROPIC_API_KEY:` と聞かれたら、Anthropic Console で発行した API キーを貼り付けて Enter を押します。入力した文字は画面に出ません。
    - Laravel Cloud とは別のキーを発行しておくと、片方だけを止められます。
    - 空のまま Enter を押すと、AI 機能は固定の応答（課金なし）で動きます。
4. 10〜20 分ほどで、`ワーカーが応答しました` と `完了しました` が出れば終わりです。
5. 最後に再起動の案内が出たら `sudo reboot` を実行します。1〜2 分で戻り、各サービスは自動で起動します。

途中で止まったら、表示されたエラーを確かめ、原因を直して同じコマンドをもう一度実行します。済んだ手順は飛ばします。

### setup.sh がしていること

| 手順 | 内容                                                                                                                      |
| ---- | ------------------------------------------------------------------------------------------------------------------------- |
| 1    | スワップ 2GB を作る                                                                                                       |
| 2    | OS を更新し、nginx・MySQL・certbot を入れる。セキュリティ更新を毎日自動で当てる設定にする                                 |
| 3    | PHP 8.4 を入れる（Ubuntu 24.04 の標準は 8.3 で、`symfony/console` 8.x の要件 8.4.1 を満たさないため）                     |
| 4    | Composer と Node.js 22（CI と同じ版）を入れる                                                                             |
| 5    | アプリ専用のユーザー `careloop` を作り、`/var/www/care-loop` に main を取得する                                           |
| 6    | `deploy/lightsail/env.production` から `.env` を作り、鍵とパスワードを生成して埋める                                      |
| 7    | MySQL を 1GB 向けに絞り、データベースとユーザーを作る                                                                     |
| 8    | `composer install`・`npm ci`・`npm run build`・`migrate`。データが空のときだけデモデータを入れる                          |
| 9    | PHP-FPM・nginx・キューワーカー（`careloop-queue.service`）・毎分の予定確認（`careloop-schedule.timer`）を設定して起動する |
| 10   | ドメインがこのサーバーを向いていれば、Let's Encrypt の証明書を取り、http を https へ転送する                              |

### 鍵とパスワード

`APP_KEY`・`BLIND_INDEX_KEY`・データベースのパスワードは、サーバーの中で生成して `/var/www/care-loop/.env` にだけ書きます。画面にも出さず、`.env` は `careloop` ユーザーしか読めません。

**一度作った鍵は変えません。** `APP_KEY` を変えると暗号化して保存したご利用者の氏名や住所が読めなくなり、`BLIND_INDEX_KEY` を変えると氏名カナの検索が効かなくなります。`setup.sh` を再実行しても、値が入っていれば作り直しません。

### HTTPS の証明書

`setup.sh` は certbot に `--agree-tos` を渡します。実行すると、[Let's Encrypt の利用規約](https://letsencrypt.org/repository/)に同意したことになります。

証明書の有効期限は 90 日です。certbot が入れる systemd のタイマーが、期限の前に自動で更新します。

## 6. 動作確認

画面の確認は、Laravel Cloud 版と同じ表（[02 の 6 章](02_デプロイ手順.md#6-動作確認)）を使います。そのうえで、このサーバーならではの確認をブラウザ SSH で行います。

| 確認項目       | 操作                                                                         | 期待する結果                            |
| -------------- | ---------------------------------------------------------------------------- | --------------------------------------- |
| ワーカー       | `sudo systemctl status careloop-queue`                                       | `active (running)`                      |
| 予定の確認     | `systemctl list-timers careloop-schedule`                                    | 次の実行が1分以内に入っている           |
| キューの疎通   | `cd /var/www/care-loop && sudo -u careloop php artisan careloop:queue-check` | `ワーカーが応答しました`                |
| HTTPS への転送 | ブラウザで `http://`（s なし）のアドレスを開く                               | `https://` に切り替わり、鍵マークが出る |
| 証明書の更新   | `sudo certbot renew --dry-run`                                               | 更新の予行演習が成功する                |
| 再起動のあと   | `sudo reboot` の 2 分後にサイトを開き、キューの疎通をもう一度確かめる        | 手で何もしなくても元どおり動いている    |

## 7. 更新するとき

**main にマージしても、このサーバーには自動で反映されません。** Laravel Cloud との一番大きな違いです。マージしたら、ブラウザ SSH で次を実行します。

```bash
sudo bash /var/www/care-loop/deploy/lightsail/deploy.sh
```

`deploy.sh` は次の順に進みます。

1. 最新の main を取得する（変更がなければ何もしない。作り直すときは `--force`）
2. メンテナンス画面に切り替える
3. `composer install`・`npm ci`・`npm run build`
4. `migrate` と `optimize`（設定・ルート・画面のキャッシュ）
5. PHP に新しいコードを読み直させ、ワーカーを実行中の AI 処理が終わってから立ち上げ直す
6. メンテナンス画面を外す

**失敗したときは、メンテナンス画面のまま止めます。** 崩れた画面を見せるより「メンテナンス中」のほうが見る人に親切で、作者も失敗に気づけるためです。原因を直して、もう一度実行します。

## 9. 困ったとき

| 症状                          | 見るところ                                                                           |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| 画面が 500 エラーになる       | `sudo tail -n 50 /var/www/care-loop/storage/logs/laravel-$(date +%F).log`            |
| 502 Bad Gateway と出る        | `sudo systemctl status php8.4-fpm`（PHP が止まっている）                             |
| AI が「待機中」のまま進まない | `sudo systemctl status careloop-queue` と `sudo journalctl -u careloop-queue -n 50`  |
| 動きが重い、ときどき落ちる    | `free -h` でメモリとスワップを見る。スワップを使い続けているなら、2GB のプランへ移す |
| 空き容量が気になる            | `df -h /`                                                                            |

## 10. 費用と、やめるとき

| 項目                   | 料金                                                      | 実際の請求の見込み                                               |
| ---------------------- | --------------------------------------------------------- | ---------------------------------------------------------------- |
| Lightsail（$7 プラン） | 1 時間ごとの課金で、**月 $7 が上限**。通信量 2TB まで込み | 月 $7 ＋ 消費税。デモの通信量で 2TB を超えることはない           |
| 静的 IP                | インスタンスに付けている間は無料                          | 0 円                                                             |
| スナップショット       | $0.05 / GB・月                                            | 使わなければ 0 円。デモデータは 8 章で作り直せるので必須ではない |
| ドメイン               | 登録会社と種類による（年額）                              | 年に数百〜2,000 円程度                                           |
| Claude API             | `LLM_MONTHLY_BUDGET_USD=3` で止まる                       | 環境ごとの上限なので、Laravel Cloud と並行する間は合計 $6 まで   |

**サーバーを「停止」しても課金は続きます。** やめるときは、インスタンスを **削除** し、静的 IP も **解放** します。付け先のない静的 IP は、1 時間ごとに課金されます。

## 11. 1 台に置くうえでのセキュリティの判断

- SSH はブラウザの SSH 画面からだけにする（3 章）
- MySQL は外に開けない。`bind-address = 127.0.0.1` とファイアウォールの二重で閉じる
- `.env` は `careloop` ユーザーだけが読める（権限 600）
- OS のセキュリティ更新は毎日自動で当てる
- PHP はアプリ専用のユーザーで動かし、nginx（`www-data`）にはアプリのファイルへの書き込み権限を渡さない

鍵をアプリケーションサーバーの上に置いている限り、サーバーが侵害されれば鍵も取られます。この限界と、実運用での対策（AWS KMS などの鍵管理サービス）は、要件定義書の 9.3 節に書いています。
